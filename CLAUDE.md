# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Commands

- **Dev server:** `bun run dev` (Vite)
- **Build:** `bun run build` (tsc + Vite)
- **Lint:** `bun run lint` (ESLint 9 flat config)
- **Preview prod build:** `bun run preview`

## What This Is

Sound Typer is a browser app around an audio file: a rhythm game generated from it (game mode, the default), or a typewriter that "types" text in sync with the music. In the typewriter louder audio types faster; detected hits (drums, sudden spikes) burst text in and trigger screenshake. Users can load audio files, customize text sources, and tweak how it feels (speed, dynamics, punch, shake, glow) in the Settings modal. There's no toolbar: every mode runs full screen in the same shell (`Stage`), with the song bar on top and the pause menu, where the typewriter is one of the styles to pick.

**Game mode** is a procedurally generated rhythm game, in one of four styles: bullet hell (dodge patterns fired on the hits), Shapes (Just Shapes & Beats style: dash through telegraphed shapes that land on the beat, rewind to checkpoints on death), Wave (Geometry Dash wave: hold to fly up, release to fly down, through a scrolling level that turns on the hits) or Shield (fixed in the centre, turn a shield to block spears landing on the hits).

## Architecture

React 19 + TypeScript + Vite. No router, no state library — single-page app with all state in `App.tsx`.

**Core data flow:** Audio file → decoded `AudioBuffer` → offline analysis in a Web Worker (`TrackAnalysis`: loudness curve, activity, timestamped hits with strength) → each rAF frame, `TypingDriver.step(audiblePosition, dt)` turns the analysis into flow chars + burst chars + hits → `Typewriter.frame()` types and applies shake/glow; `Visualizer.draw()` renders spectrum + timeline.

Key pieces:
- **`src/audio/analysis.ts`** — Pure offline analysis (no DOM; runnable in Bun for testing). STFT → K-weighted loudness normalized per track; SuperFlux-style onset detection on a semitone filterbank with centered adaptive threshold, post-hit masking; hit strength = flux rank OR loudness surprise; per hit lowness and brightness (kick vs hat). Also a brightness curve (spectral centroid), a tonal curve (cheap harmonic/percussive split: median along time vs across bands; high for held notes and pads), and a beat grid: global tempo from the novelty autocorrelation, beats by dynamic programming (Ellis 2007), doubled when it turns out to be half the song's (`halfSpeed`: a fast song with accented pairs of beats; the doubled tempo at most `DOUBLE_MAX` (fast electronic music goes past 200), at least `DOUBLE_HITS` hits per beat, and the half-beat's hit rivalling the beat's in at least `DOUBLE_SHARE` of the beats; a slow song's busy figures leave its half-beats weak, a moderate song has too few hits), bar phase (4/4 assumed) by a Viterbi pass over kick, harmony change and onset evidence (`beatTimes`, `beatInBar`). Downbeats are the least reliable part. Held notes (`noteStart`/`noteEnd`/`noteStrength`, `heldNotes`: partial tracking on the filterbank; a peak that keeps its pitch and level, so plucks and drums don't count) and a sound fingerprint (`print`: pitch classes plus band levels at `PRINT_FPS`, for finding repeats).
- **`src/audio/analyzeBuffer.ts`** / **`analysis.worker.ts`** — Downmix/resample to 22.05 kHz mono via `OfflineAudioContext`, run analysis in a worker.
- **`src/audio/lyrics.ts`** — Timed lyrics (per line) from a file's own tags: `readLyrics` (FLAC Vorbis comments; ID3v2.3/2.4 `SYLT`, `USLT`, `TXXX`; reads only the tags, never throws) and the LRC parser. A line ends at the next one's start or after a hold (`HOLD`); an empty line is a gap. DOM-free.
- **`src/audio/driver.ts`** — `TypingDriver`: time-based (framerate independent) typing from the analysis; handles seeks by resyncing the hit cursor.
- **`src/hooks/useAudioEngine.ts`** — Web Audio API wrapper: load/play/pause/seek/volume. `getPosition()` returns the *audible* position (output latency compensated via `getOutputTimestamp`).
- **`src/hooks/useAnimationLoop.ts`** — rAF loop calling `onFrame(dt)`.
- **`src/components/Typewriter.tsx`** — Types via imperative `frame(pos, frame, dt)` inside a `Stage`, the visualizer as its backdrop. Spring-physics screenshake, hit glow (`--hit` CSS var), word snapping on strong hits, a cursor in the games' player colour. `finish()`/`start()` like `Game`. Doesn't pause when the window loses focus (nothing to play); settings and clearing are in its corner so the feel can be tuned while it runs.
- **`src/components/Stage.tsx`** — The shell every mode is played in (`Game` and `Typewriter` each render one around their content): song bar, menu, volume toast, idle cursor, and the keys about the song (Esc/P toggle pause, `,`/`.` step through checkpoints or 10 s, volume, fullscreen, 1–5 pick the style while paused; anything else goes to the mode's `onKey`). `pauseAway` modes pause when the window loses focus, the tab is hidden or fullscreen is left. `Session` (built in `App.tsx`) is the song and everything else that's the same in every mode. Files can be dropped anywhere (window listeners in `App.tsx`). Icons are in `icons.tsx`.
- **`src/components/Visualizer.tsx`** — Canvas: log-frequency spectrum + scrolling timeline of intensity and hits. A strip above the game (off by default), a dimmed `backdrop` behind the typewriter's text.
- **`src/components/Settings.tsx`** — Modal for tuning, only what the current mode uses: typing feel (`FeelPrefs`, stored in `sound-typer-prefs`), game, effects and layout (`SettingsState`, stored in `sound-typer-settings`; also holds the current mode and the style and difficulty picked in the game's menu), reset to defaults.

Game mode (`src/game/`; everything except the renderers is DOM-free and runnable in Bun). Four styles behind one `GameEngine` interface (`types.ts`), picked by `SettingsState.gameStyle`:
- **`common.ts`** — Seeded RNG (per track, same for every difficulty), section splitting (~6–13 s, snapped to strong hits; Bullet hell), song structure (`songParts`: the intensity curve fit with flat parts, boundaries moved onto the sharpest change and the hit there; Shapes and Wave), sliding per-second budget, shake spring, canvas setup, `HealthPips` (health drawn at the player by the Shapes, Wave and Shield renderers: a row of pips under it, bright after a hit, blinking red on the last one; off with the `showHealth` setting). Play area zoom: Shapes and Bullet hell scale their play area around its centre so attacks cover about the same share of it (`Coverage`, `scaleFor`: from 0.4 = 2.5x zoom when little is going on to ~1.1 when packed; grows fast, shrinks slowly, `easeScale`). Shapes precomputes it from the chart (`zoomCurve`, looking ~0.75 s ahead, and no single hazard spans more than 40% of the area), so it's a pure function of song time; Bullet hell follows the live bullets (each with some dodging room, culled only at the widest area so a small area doesn't feed on itself). Hazards and emitters land in the area as it is when they appear, the player is pushed in by its edges, the camera always shows exactly the area (`GameEngine.scale`, also used to map touches), all scaled by the `cameraZoom` setting. `hitWeights` rates every hit: `prom` (how much it stands out from the hits within ±4 s, so quiet passages still have standouts; decides whether/what spawns) and `heft` (strength × intensity; decides how big, fast and wide the attack is).
- **`lyrics.ts`** — `drawLyrics`: the line being sung, big and faint behind the game (`EffectSettings.lyrics`, null when the `showLyrics` setting is off, the default, or the song has none). A pure function of song time. Every renderer calls it with its own look, before anything that can hurt: Shapes before the rest's dimming, Wave over the wall fills (they cover most of the view), Shield in its monospace near the bottom. Kept faint so it doesn't compete with telegraphs.
- **`bullets/`** — Bullet hell. `chart.ts` schedules patterns from emitters per section: pellets (weak hits), aimed fans (crisp), rings (bassy/strong), telegraphed lasers (strongest), spiral streams in loud sections. `sim.ts` spawns them as the audio position passes, advances bullets by audio time, handles collisions and grazes (sparks only). `render.ts` draws (sprite-cached glowing bullets, charge-up telegraphs).
- **`shapes/`** — Just Shapes & Beats style. `chart.ts` splits the song into `songParts`, each with a role (calm, main, build, drop, break; from its song-relative level and the jump from the part before) and a colour per role (the renderer eases into it and washes the screen on part changes); the last 3–8 s before a drop is its build (only standout hits, mostly a trail, half budget, the arena squeezes in to `BUILD_SQUEEZE` and the zoom look-ahead stops at the drop so it bursts open on the beat) and a drop opens with a cross of bars bursting into a ring of shots. Themes (field, bars, steps, walls, spinner, rain, grid) come in runs of bars (`shapesRuns`, on the beat grid; 2 s bars where there's none): a run goes on while its bars sound alike (`Feel`: density, kick/hat/heavy shares, tonal, intensity) and ends when the music changes (`RUN_CHANGE`, or at a 4-bar phrase once it drifted, or after `RUN_MAX_BARS`), never crossing a section, so attacks follow the music rather than a timer. Each run's theme is weighted by its feel (accented → bars, kicks and punchy → walls, steady beat → steps, hats → rain, sustained → spinner, steady kicks → grid; drops lean on the big themes) and a run that sounds like an earlier one (`RUN_RECALL`) reuses its theme, (the grid not right after itself or past `RECENT_MAX` uses in the last `RECENT_RUNS` runs; each recent use also makes rolling a theme less likely). Repeats (`songRepeats`: diagonals in a beat-by-beat similarity of `print`, at least `REPEAT_LAG` beats back) go further: a repeated stretch changes runs where the original did and takes its theme and `seed`; placement dice come from the seed and the hit's 16th note in the run, so a refrain comes back with the same attacks. Within a run every hit is a voice (kick: bassy, hat: bright, else snare) and the theme gives each voice its own attack, so no one attack takes over the screen: e.g. in steps the march is the kick line (beats 1 and 3 when a run has few kicks; it pauses when they do) while snares pop up, hats fire volleys and heavy hits slam a bar across. Cooldowns that are about the music count in beats (seekers `seekerBeats`, ray bursts, build volleys, walls `wallBars` with a `WALL_GAP_MIN` floor); the ones that guarantee walking time stay in seconds. Walls only come on the heaviest hit of a bar; the steps march and the bomb trail turn on downbeats. Hits become hazards that warn, go solid on the beat, then shrink; every hazard's geometry is a pure function of time (`geometry()`), shared by collisions and drawing. Bars across the arena are the main element; small hazards come in predictable patterns (bomb trails, shot volleys), pop-ups are placed apart, and homing is limited to small, spaced-out seekers plus targeted bars (they lock onto the player when the warning starts). Every hazard warns at least long enough to walk out of it (`warnFor`), so a dash is never forced. An idle fallback fills silences longer than `idleMax` when the music has hits. Hits are classified by `prom` and every hazard's size, width, speed, lifetime and budget cost scale with `heft` (heavy hits, only from intensity `HEAVY_INTEN` up, get walls, crosses, ray bursts and pop-ups that burst into rings of shots; homing bars only from `TARGET_INTEN` up). Walls lurch forward on the beats of their sweep (`kicks`, `wallProgress`), the heaviest come from both sides at once with gaps lined up. Steps lanes end just before the march's next beat (`stepSlack` before it), so the march lands on the beat without two lanes ever being solid; in dense streams a lesser hit yields to a clearly bigger one right behind it. The spawn budget and projectile speeds scale with the music's intensity (`intensityAt` in `common.ts`, the typewriter's curve); no single obstacle covers more than half the arena. Drive (`raveCurve`: smoothed intensity times hit density, less in calm parts and builds) is how hard the music raves: raving passages (`RAVE_*`) get wider bars, bigger pop-ups and shots, longer-lived hazards, more budget, lesser hits spawning too, walls up to twice as often (on the half bar's heaviest hit), a steps march mirrored from the other side, and a zoom that targets more coverage and follows the attacks' average over its look-ahead instead of their peak, so the screen stays packed. Hazards that stay solid a while (not walls, shots, grids or lanes) pulse on the music's hits (`pulses`: a small pop in `geometry()` and a lighter tint in the renderer), so what's on screen moves with every hit. The renderer is intensity-driven too (speed streaks, camera punch on strong hits, bass thump, pumping background). Spinner beams follow a sampled `BeamPath` (drifting pivot, loudness-driven spin, kicks on hits) but only live while a sustained sound holds (`beamHolds`: the tonal curve, averaged over a beat, above the run's average with hysteresis; dips up to a beat don't end a hold; at least a bar unless the level really drops, at most `BEAM_BARS` bars, leaving on a beat; a beat apart, a bar after one that hit the cap); spinners only fit runs with real sustain (`SPINNER_TONAL`) and at least one hold. Loud held notes get the same beam in any theme (`NOTE_BEAM_*`, not in builds): it lands on the note's start, lasts as long as the note, and hits under it play the spinner's attacks. Big hits fire ray bursts from the pivot. Grid: the bar's heaviest hit flashes half a checkerboard and the next bar's the other half, then `GRID_REST_BARS` empty bars (`grid`; warned to walk half a cell, walking time between flashes; not on easy; doesn't count towards the zoom's coverage), kicks and snares pop up. Rests (`findRests`: the loudness drops out for 0.2–3 s and comes back on a hit): every hazard solid when the music stops freezes (`freeze`; geometry runs on the hazard's own clock, `localTime`, and its `end` moves back), nothing spawns in the silence, and the return hit snaps pop-ups warned from the start of the silence (the first bursting into a ring; a drop's slam replaces it); the renderer stops the background and dims it, then flashes on the return. `sim.ts`: movement, dash (invulnerable, cooldown), health, checkpoints (`CHECKPOINT_EVERY` to `CHECKPOINT_MAX` s apart, on a section start, else a run start, else a bar line); running out of health asks Game to rewind the song (`takeRewind`), which doesn't count as a seek.
- **`wave/`** — Geometry Dash wave. `chart.ts` lays an ideal path at the wave's slope that turns on hits (gap and strength threshold scale with intensity), sampled at `RATE` per second together with world x (`xs`, scroll speed per section), then builds around it with clearance: tunnels (`top`/`bot` walls, height = `r + 2·vy·window`, so the difficulty's timing window is explicit), looser spiked corridors with saws outside turns or block columns with a gap, mini sections (slope 2), spam sections (bursts of `SPAM_LEN` s with `SPAM_BREAK` s of plain tunnel between: a straight or gently sloped corridor only `spamStroke` seconds of flight tall, so staying inside takes ~1.5/2/2.6 taps per second (at least `SPAM_MIN_FREE` units of room, more on slopes); the ideal path turns on beats near its centre line and is forced to turn at the corridor's edge), gravity-flipped parts (`flip`: holding flies down; normal/hard, after 20 s, preferably on intensity jumps; the sim inverts input and the renderer draws a gravity portal). Sections come from the song's structure (`songParts`, in `common.ts`; neighbours that get the same speed stage merge), each part gets a speed stage (`SPEED_STAGES`) from its intensity on a song-relative scale, and the busiest intense parts (the drops) go mini; long parts are split only to change obstacles, picked by the music's character (bassy → pillars, heavy accents → saws, dense → spam, calm → tunnel). Turns use `prom` (calm parts take long sweeps through roomier tunnels); heavier turns bite teeth into the outside wall (keeping 3/4 of the timing slack) and size the saws. Walls are filtered so they never close in faster than the wave flies (fair tunnel entrances). The level is static, so seeking needs no replay. `sim.ts` integrates the wave by audio time with sub-steps; a hit puts it back on the path; health/checkpoints/rewinds work like Shapes. The level is open (no floor or ceiling; the path is never bounded and takes any hit after flying straight `MAX_STRAIGHT`). `render.ts`: the camera follows the wave vertically and zooms with the speed stage (`ZOOM_SLOW`..`ZOOM_FAST`); flat zinc look, one color per speed stage, zigzag trail, beat lines, speed portals and meter.
- **`shield/`** — Shield: the player can't move, only face up/right/down/left. `chart.ts` reuses Shapes' structure (`shapesSections` roles, `shapesRuns`, `findRests`, `barStarts`) and its drive (`raveCurve`). How much it plays follows the drive: the difficulty's `rate` (spears a second, from calm to raving) sets how many notes a bar gets. The rhythm comes from the bars, not from single hits: `slotStats` lets all bars of the runs sharing a seed vote on a 16-slot grid, `runNotes` keeps the slots that recur most (`SLOT_KEEP`, on the difficulty's grid, `gridTime`: the finest of sixteenths/eighths/quarters at least that long, so a fast song read at half its tempo isn't held to quarters; as many as the run's drive asks for; each with its majority voice; a hit belongs to the run of the slot it rounds to, so one just before a run's first bar line is its downbeat), plays them in every bar (filling in where the detector missed one, `SLOT_FILL`), then tops each bar up with its standout hits to that bar's own count (lesser hits where it raves, `RAVE_PROM`; the hardest always get in, `ACCENT_*`). Each run dances (`Dance`, from its Shapes theme, `THEME_DANCES`; the theme's other dance or `FALLBACK_DANCES` when it doesn't fit: kit needs two voices, sway only below `SWAY_DRIVE`, no stomp or sway right after one; a repeat dances like its original): kit (kicks from one side, snares from the opposite, hats follow), pingpong, zigzag, roll, stomp (a side per beat), sway (half bars, sustained music); builds rise (round and round, the turns speeding up towards the drop). A note's side is a pure function of its place in the run (`danceSide`) and the seed, so bars that sound alike play alike and a repeat comes back identical; the side changes once per turn unit (a sixteenth, an eighth, a beat, ...: the shortest the difficulty's `turnGap` allows, longer when calm, `TURN_CALM`; stomp and sway at least `DANCE_TIME` seconds, calm parts `CALM_TURN`). Sides then settle in order: notes too close for their sides (`minGap` on one side, `turnGap` across) don't both stay, the lesser gives way, so a fast stream breathes before it turns; a streak on one side turns after `STREAK_NOTES` notes or `STREAK_BARS` bars. Spears: heavy (the heaviest note around, within a bar or half a bar where it raves (at least `HEAVY_WIN` seconds), standing `HEAVY_LIFT` above its neighbours, or a hard downbeat of a phrase (of a bar where it raves); also a drop's first hit and a rest's return; no cooldown; much faster; bigger sprite, its lane lights up in flight, a blast on landing), reverse (flies in tail first from the opposite side, jumps over on a beat if one's near, leaving `reverseRead` to arrive; not on easy), lance (loud held notes that start on a hit, not in builds, drops or where it raves (`LANCE_DRIVE`), at most `LANCE_BARS` bars (ending on a bar line if the note goes on), `LANCE_REST_BARS` apart; lasts its note: head and tail fly at the same speed, so its length is the note's); the sprite shows the voice. Speed stages as in Wave (`speedParts`, `SPEED_STAGES`): a spear is launched at the speed and border (`borderAt`, `Spear.far`) of its launch moment, its flight a whole number of half beats, so spears that land on the grid leave on it, and a change never moves a landing. A build squeezes the border (`BUILD_SQUEEZE`) and a drop bursts it open. Rests: flight runs on `localTime`, so spears hang in the air while the music is silent and land when it returns. Spears on one lane come into view in landing order, so none overtakes another there; across lanes a heavy may come into view after a spear that lands first (`launches` is the spawn order, `maxLead` bounds what's in view). `sim.ts`: a spear is blocked if the shield faces it on arrival, left that side up to `EARLY` ago or turns within the difficulty's `late`; a lance has to be held till its end. Short `INVULN` after a hit; health/checkpoints/rewinds work like Wave. `GameInput.facing` latches the last direction key pressed; a finger aims from the centre. `render.ts`: chunky pixel look on a fixed cell grid (`CELL`): black, flat sprites in four rotations, no glow, hard flashes, and everything follows the music: screen and border pump on kicks, tips pop on launches, lanes crawl per beat, dust rushes with the intensity, blocks lurch the camera along the spear (`LURCH`), a rest stops and dims it all; the camera keeps the border at `BORDER_SCREEN` (scaled by `cameraZoom`); stage colour on the border (the build's in a build), FASTER/SLOWER callout; the shield stays teal while it holds a lance.
- **`src/components/Game.tsx`** — Canvas + input (keyboard and touch incl. dash gestures; the mouse never plays, it's for the song bar, the wheel is the volume) in a `Stage`. Reuses a `TypingDriver` only to get music hits for shake/glow. App calls `frame()` each rAF, `start()` before playback and `finish()` when the song ends. Jumps go through `seekTo` (`GameEngine.jump()` then a zero-length step: full health, `SEEK_GRACE` of invulnerability, shown right away while paused); a new engine (style or difficulty changed mid-song) steps to the current position, so the song goes on from there. The screen's edges glow red on the last health (also off with `showHealth`).
- **`src/components/SongBar.tsx`** — Playback bar at the top: a thin line with the checkpoints while playing, opening on hover or pause into the song's intensity outline; click or drag to jump, snapping to checkpoints (while paused it previews each place and the menu hides). Clicking the time while paused types one in.
- **`src/components/Menu.tsx`** — The card shown whenever nothing is running (no song, ready, paused, song complete): song picker, style (`src/game/options.ts`, the typewriter included), difficulty (the text to type for the typewriter), resume and the mode's actions, keys, volume, visualizer, fullscreen, settings. It keeps its height across styles, so every style fills the same rows.

**Persistence:** Three localStorage keys (`sound-typer-prefs`, `sound-typer-text-source`, `sound-typer-settings`) store user preferences, custom text and settings. Game mode has no score: the HUD shows hits (health is at the player), and the end card shows hits taken and rewinds.
